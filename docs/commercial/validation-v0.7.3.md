# 0.6.4 / 0.7.3 包内文件编辑流程

2026-10-19，Windows x64，`paid-version` 分支。免费版 0.6.4，收费测试版 0.7.3。

## 行为依据

按 Bandizip 的[包内文件打开说明](https://cn.bandisoft.com/bandizip/help/how-to-open-a-file-in-an-archive-without-extraction/)和[编辑保存说明](https://cn.bandisoft.com/bandizip/help/how-to-edit-and-save-file-in-archive-directly/)实现：提取临时副本，调用本地关联程序；保存并关闭编辑器后检测修改，ZIP / ZIPX 询问是否写回；退出时清理临时文件。

## 已实现

- 双击或 Enter 通过 `UseShellExecute=true` / `Verb=open` 调用 Windows 文件关联，不再固定用记事本打开文本及源码。沿用程序、安装包和快捷方式先手动解压的现有规则。
- 每次打开记录原压缩包、原条目路径、原始内容 SHA-256、本地副本和返回的编辑器进程。监控编辑器退出；内容未变不询问，运行中保存不询问。确认窗显示实际原包及条目，“是”写回，“否”不改变原包。
- 回写仅用于实际 ZIP 容器的 ZIP / ZIPX 文件；7Z、RAR 等仅通过关联程序打开，不提供编辑回写。深层目录仍使用上一版的长路径处理和短临时文件路径，写回目标始终是原包内的完整条目路径。
- 回写进入现有任务队列和收费授权门禁。先校验原条目的内容仍与打开时一致，再更新同盘暂存包；完整性、条目结构、其他条目 CRC/大小/加密状态及修改后的内容全部校验后，检查原包及编辑副本没有再改变，最后用 File.Replace 提交。取消、冲突或原包被占用时保留原包。
- 同一原包的不同条目可独立回写并保留先前更新；同一条目的过期编辑会被拒绝。切换当前浏览的压缩包不会改变会话的原包，也不会让回写强行切回原视图。
- 正常副本在退出时清理；回写失败的副本保留并显示找回路径。编辑器仍运行时退出会提示，因为退出之后不能继续自动回写。没有清理旧版本遗留副本或修改已有授权缓存。

Windows 文件关联调用可能不返回新进程，或者新启动的短命进程将文件交给已运行实例后退出。此时无法可靠判断实际编辑窗口何时关闭；NZIP 在未取得进程时显示提示，不自动猜测回写时机。官方说明也指出复用窗口或部分编辑软件的兼容限制。参考微软 [Process.Start 返回值说明](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.start?view=netframework-4.8)。不能在编辑器仍使用副本时提前关闭 NZIP，并期望继续自动回写。

引擎专项验证了嵌套中文路径、ZIP / ZIPX、相同大小与时间戳的内容修改、注释和其他条目保留、加密 ZIP、独立编辑会话合并、过期编辑冲突、非法参数、取消和隐式父目录。

原生界面测试记录 ShellExecute 请求以核对关联程序调用参数，使用真实隐藏子进程模拟编辑器存活/退出，不更改系统文件关联、不启动客户的真实编辑器。测试实际打开“更新压缩包”确认窗，分别点击“是”和“否”；验证进程未退出时不询问、未修改退出不询问、写回后真实 ZIP 内容、原包被文件句柄占用时原包不变及副本保留、切换压缩包、7Z 不提供回写，以及退出清理函数的正常/失败副本处理。

首轮收费界面测试在原有 ZIP 注释步骤出现一次未写入失败。诊断结果与测试数据已保留；随后加入界面刷新完成、按钮就绪和实际注释窗打开的断言，最终两个版本的完整界面回归均通过，首轮失败不计为通过。未声称已验证所有编辑器的进程复用方式或全部 ZIPX 压缩方法。

此次没有重新运行需要覆盖/删除已有本机预览授权缓存的未激活脚本；该脚本已加入 writeback 门禁检查。收费版测试使用已有有效的隔离测试证书，无正式域名或真实邮件发送。AMSI 回归仅验证不可用时的明确反馈，不代表实际杀毒成功。

WiX 生成 MSI 时提示 LGHT1105，受系统策略限制无法运行 ICE 校验；实际安装、升级、卸载未在本次执行。没有改变系统安全策略。
