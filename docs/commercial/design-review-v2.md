# NZIP 收费版设计补充评审 v2

日期：2026-10-11。当前设计：[v1.2](design-v1.2.md)。
方式：根据用户新的产品决策进行静态场景与一致性复核；没有业务实现、并发运行测试或第三方安全认证。

## 决策与结论

用户明确接受：“可以接受这种风险，允许客户自动解绑、释放名额并换机。”因此历史评审 R01 关于循环分享的观察继续成立，但它现在是已接受的业务取舍，不是阻止实施的问题。

v1.2 采用长期离线凭证和客户自助解绑。默认 3 个名额计数当前 active 登记，不计数历史发证数；解除登记可以立即让新设备占位。旧副本或凭证备份可能继续离线运行，不要求系统消灭这一可能性。

设计层面可进入实施。剩余必须验证的是激活/解绑计数一致、延迟请求安全、客户管理权限和正常用户的故障恢复，不能再以“不支持即时撤销永久凭证”为理由取消自助换机。

## 对历史评审的调整

| 历史项 | 新处理 |
| --- | --- |
| R01 自动解绑带来循环分享 | 用户接受，取消累计发证上限及人工批准常规换机的措施；明确计数边界和销售文案 |
| R05 人工恢复可能被滥用 | 常规恢复改为客户自助解绑；额外发证不再是主要换机路径。邮箱丢失等人工例外仍核验订单 |
| R03 发证并发与幂等 | 保留并扩展到激活/解绑跨操作事务、登记代次及响应丢失恢复 |
| R02、R04、R06、R07、R08 | 通用入口、设备识别、签名、本地可靠性、测试隔离和发布要求继续有效，按 v1.2 的自助管理流程解释 |

## 补充发现及处理

| 编号 | 级别 | 失败场景 | v1.2 措施 | 状态 |
| --- | --- | --- | --- | --- |
| N01 | P1 | 历史设备重新激活直接复用旧证而不检查占位，绕过服务器登记上限 | active 才能直接重试返回；deactivated 必须检查空位并占位、递增代次、产生新发证记录 | 设计已明确，待实施 |
| N02 | P1 | 重复解绑多次减计数，或旧请求解绑已经重新激活的设备 | 状态迁移幂等，核对 bindingId + generation；旧代次不影响新代次；以 active 行计数，不使用无约束的加减计数器 | 设计已明确，待实施 |
| N03 | P1 | 先删除本地授权再调用服务器，断网后客户既不能用也没释放名额 | 服务端事务成功后再清本地；响应丢失按 requestId 确认结果；错误时保留原授权 | 设计已明确，待实施 |
| N04 | P1 | 仅凭转发授权码能移除客户全部设备，或设备编号可越权解绑 | 本机使用当前绑定的管理令牌，网页管理核验订单邮箱；令牌、会话均限制到授权与代次 | 设计已明确，待实施 |
| N05 | P2 | 解绑之后重放旧激活请求，返回已不占位的证书并谎报激活成功 | 幂等响应核对当前 active 代次；状态变化则要求新激活请求，不恢复旧占位 | 设计已明确，待实施 |
| N06 | P2 | 用户离线导入证书后没有本机管理令牌，或旧设备已经损坏，无法自助释放 | 购买邮箱验证后可远程移除，无需旧设备在线；常规场景不依赖人工批准 | 设计已明确，待实施 |
| N07 | P2 | 多个进程或其他 Windows 用户保留旧内存/凭证，无法证明本机所有副本停止 | 正常本机解绑清当前用户可访问缓存与本次进程状态，已有任务完成；其他副本继续有效归入已接受的离线风险 | 已接受，不作为全局撤销验收 |

## 当前验收场景

以下仍是待实现验收条件，不表示已经运行通过：

1. 三个登记占满后拒绝第四个新登记，并提供自助设备管理入口。解绑一个后，无人工审批即可激活第四个；历史发证数可达到四个或更多。
2. 反复执行“激活新设备→解绑旧登记”，允许持续换机，不增加普通换机冷却期或累计发证封锁。服务器 active 登记始终不超过额度，旧离线凭证仍可能工作。
3. 在同一个空位上并发激活十个新实例，最多一个新增 active 登记；并发激活/解绑后计数与数据库状态一致。
4. 重复提交同代次解绑一百次，只释放一次；提交旧代次的延迟解绑不影响已重新激活的新代次。
5. 同设备重复激活不占额外名额；已解绑历史设备重新激活仍需检查空位，不能因历史记录存在直接绕过上限。
6. 解绑事务提交失败、签名失败、客户端崩溃和网络响应丢失分别演练；重试能够收敛到真实状态，不能先删好凭证或虚报释放成功。
7. 原激活 requestId 所属代次已被移除时，重试不能把旧响应当成新的成功占位；客户端能以新请求正常重新激活。
8. 另一份授权的管理会话、设备令牌、旧代次令牌、过期验证码和仅知道设备编号的请求均不能解绑目标登记。
9. 原设备损坏或 Windows 已重装，购买邮箱验证后可移除旧登记并激活；纯离线导入凭证也有同一自助释放路径。
10. 本机解绑成功清除当前用户可访问的本地授权，阻止本进程新收费任务，已开始任务完成；断网解绑失败则保留本地授权和服务端占位，提示尚未解绑。
11. 远程解绑后，离线旧机或备份恢复的旧凭证可以继续通过本地验证，这是预期取舍；不能偷偷增加启动联网、周期吊销或时间回拨封锁。
12. 沿用历史评审的跨实例复制、签名篡改、核心入口覆盖、密钥/测试隔离、性能、旧版并存和发布验收。

## 与 Typora 的参照边界

Typora 官方说明支持每份授权最多 3 个设备，以及本机或网页自助停用旧设备；官方离线激活令牌存在至少六个月占位限制。NZIP 借鉴激活和自助管理体验，按用户确认不引入该离线换机等待期，也不宣称其内部授权实现与 Typora 相同。[Typora 激活说明](https://support.typora.io/activation/)、[Typora 离线激活说明](https://support.typora.io/Offline-Activation/)

本次只更新设计及评审；没有修改应用、部署服务器或提交发布包。默认设备登记数、销售价格、正式条款、域名和购买邮箱验证服务配置仍需在实际发布前落定。
