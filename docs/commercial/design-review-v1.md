# NZIP 收费版设计评审 v1

> 历史评审：R01 所述循环分享风险现已由用户接受，R01/R05 的人工换机措施不再作为现行要求。当前结论见 [补充评审 v2](design-review-v2.md)，其余通用验证项继续适用。

日期：2026-10-11。评审基线：[设计 v1.0](design-v1.md)。
方式：基于当前源码、状态流转和异常场景的静态评审，由当前助手完成；没有独立评审人、实现验证、渗透测试或生产环境演练。

## 结论

v1.0 需要修订。方向符合“减少普通分享、保持客户正常使用”的目标，但自动解绑释放名额与永久离线凭证相冲突。另有入口覆盖、设备语义和并发发证问题，必须在实现前明确。

修订措施已写入 [设计 v1.1](design-v1.1.md)。v1.1 在设计层面可以进入实施；这是设计结论，不能视为授权系统已实现或具备防破解保证。所有商业参数仍是提案，首发默认 3 个自助发证名额。

## 发现与处理

| 编号 | 级别 | 问题与复现思路 | 修订措施 | 当前状态 |
| --- | --- | --- | --- | --- |
| R01 | P1 | 永久离线凭证无法撤回；激活 A、解绑 A、激活 B，重复后可让许多设备同时保留有效凭证 | 改成累计自助发证额度；没有自动释放额度的解绑；额外换机凭订单人工恢复，明确旧凭证可能继续有效 | 已纳入 v1.1，未实现 |
| R02 | P1 | 只锁按钮或任务队列会漏掉命令行及直接调用引擎的预览、剪贴板提取；未激活仍能获得包内文件 | 明确能力矩阵；共用授权服务；核心公开操作入口及静态工具入口校验；未知操作默认需要授权 | 已纳入 v1.1，未实现 |
| R03 | P1 | 并发“查额度→签发→登记”可能超发；响应丢失后的重试可能重复扣额度 | 数据库写事务内核验额度、登记与保存签名凭证，提交后返回；设备唯一约束、请求幂等和请求内容绑定 | 已纳入 v1.1，未实现 |
| R04 | P1 | “一台设备”没有定义：系统重装、不同 Windows 用户、克隆系统可能产生不同预期；缺失标识使用统一默认值会让授权通用 | 明确按 Windows 安装实例识别；同实例重装软件和不同用户复用同一登记；系统重装通过恢复流程；缺失标识不发通用证书；克隆系统不作防护保证 | 已纳入 v1.1，未实现 |
| R05 | P1 | 人工补发如果只凭授权码，分享者也能不断索取额度；恢复系统成为无限发证入口 | 额外发证核验原订单持有人，记录原因与累计发证数；不用“报告删除旧设备”作为自动释放条件 | 已纳入 v1.1，未实现 |
| R06 | P2 | 凭证 JSON 重序列化、可协商算法、密钥轮换不明确，会出现兼容性和验签漏洞；DPAPI 不能独立替代验签和设备绑定 | 固定签名算法，对原始载荷字节验签，拒绝未知 keyId/schema、重复字段和错误产品；保留旧公钥验证已有凭证 | 已纳入 v1.1，未实现 |
| R07 | P2 | 停服、缓存损坏和换用户时可能误删好凭证或强制联网；用户文件有被当前任务中断的风险 | 已激活路径不联网；激活验证失败保留已有好凭证；独立授权状态；在任务准入校验，已开始任务完成；提供导入与订单恢复 | 已纳入 v1.1，未实现 |
| R08 | P2 | 测试开关、替代用户目录、旧版注册项和旧 MIT 文案可能混淆收费边界 | 发行版无授权绕过开关；商业版独立产品/配置/安装身份；测试密钥不被正式版信任；商业条款和第三方许可分开整理 | 已纳入 v1.1，未实现 |

P1 表示会使分享限制失效或明显误伤正常用户，不能按 v1.0 原规则实施。P2 表示需要在发布前落实的可靠性、兼容性或运维约束。

## 结合源码的检查位置

| 现有位置 | 评审观察 | 实施要求 |
| --- | --- | --- |
| `native/Program.cs` | `--engine-rpc` 在创建窗口和 Backend 前直接调用 ArchiveEngine / ArchiveTools；shell 注册属于独立路径 | RPC 每项操作映射同一能力表；注册和卸载路径保持可用 |
| `native/Backend.cs` | `Enqueue`、`extract-folder` 与 `ExtractForOpen` 汇合，但不是所有引擎调用都走队列 | 任务准入与核心操作共用授权服务，不能只在 Enqueue 增加判断 |
| `native/DesktopDialogs.cs` | `Preview`、`CopyFiles` 直接调用 Engine.Extract；OpenEntry 走 ExtractForOpen | 三种内容提取都需授权；目录树与文件列表保持可浏览 |
| `native/ArchiveEngine.cs` | List / OpenRead 展开压缩 TAR 的中间层以取得列表 | 允许的目录浏览仍需工作，避免在底层所有 7z 调用上一刀切阻断；用户提取操作单独校验 |
| `native/ArchiveTools.cs`、`native/ArchiveScanner.cs` | 修复、恢复、扫描各有独立操作逻辑 | 共用能力校验，不能遗漏静态方法入口 |
| `native/DesktopWindow.cs` | `NZIP_TEST_MODE` 目前用于烟雾检查和错误显示 | 不赋予授权能力；收费版发行测试用真实测试构建和签名测试凭证 |
| `native/DesktopPreferences.cs` | 设置导入、profile 变化不能成为授权来源 | 授权不从 preferences.json / desktop.json 合并，普通设置备份不携带激活码 |
| `scripts/generate-msi.js`、`native/ShellIntegration.cs` | 当前安装和 shell 标识属于旧 NZIP | 商业版使用独立产品/升级身份及用户注册键，不能意外维护或卸载免费版 |

## 场景推演

| 场景 | v1.1 预期结果 | 剩余边界 |
| --- | --- | --- |
| A 只把安装包发给 B | B 可安装与浏览列表，需要自己的授权才能用收费能力 | 安装包允许传播 |
| A 把程序目录与授权文件一起发给 B | 正常客户端的设备绑定不匹配，拒绝导入；DPAPI 缓存跨用户/机器通常也不能直接解密 | 不保证抵抗完整系统克隆和程序修改 |
| A 分享完整授权码 | 第一个订单额度以内的新实例可能激活；超过额度停止自助发证 | 三个名额内的主动共享被接受为轻量方案的取舍 |
| A 反复卸载重装软件 | 同一 Windows 实例重新取得同一登记的凭证，不扣新额度 | 授权码需由客户妥善保留 |
| A 重装 Windows，安装标识改变 | 正常走新实例激活；无额度时核验原订单恢复 | 不承诺所有重装自动识别为同一物理电脑 |
| A 申请解绑后持续离线 | 没有自动释放额度入口；旧凭证可继续有效 | 不承诺单设备并发控制或即时撤销 |
| 客户断网、授权服务停机、系统时间改错 | 有效长期凭证的设备继续运行；没有周期到期或时间回拨封锁 | 新激活需要联网或人工离线发证 |
| 激活返回前断网，再次提交 | 相同订单和设备获得同一凭证，只消耗一次额度 | 实现须经过数据库并发与故障注入测试 |
| 超过额度的大量请求来自同一办公网络 | 限制可疑激活请求，不影响已经授权的软件操作 | IP 只能作为限流信号，不能独立判断分享或封号 |
| 旧免费版继续运行 | 行为保持不变 | 收费版不会把已交付免费版远程变成收费版 |

## 进入实施后的必要验证

以下均为待执行验收，不代表已经测试通过：

1. 在两个独立 Windows 安装实例，验证安装包、程序目录、DPAPI 缓存、导出凭证分别复制时的行为。
2. 一份授权向 10 个不同实例并发激活，默认额度最多产生 3 个不同实例凭证；同一实例 100 次重试只产生一条发证登记。
3. 分别注入数据库提交失败、响应丢失、服务重启、签名失败；不能出现可用证书已流出却未登记，或重试重复消耗额度。
4. 枚举 GUI、右键、RPC、批量任务、复制、内容查看、本地打开、扫描、修复与恢复入口；无凭证时不能提取收费操作结果。
5. 断网、无 DNS、服务器 TLS 错误、服务永久不可达、日期明显错误时，已激活设备继续完成正常任务；不替换已存在的有效凭证。
6. 在同一 Windows 实例不同账号下导入绑定该实例的证书或重新激活，验证不增加设备登记；Windows 重装执行订单恢复演练。
7. 测试正式版不接受测试签名、未知公钥、错误产品、修改载荷、重复 JSON 字段、恶意大文件和环境变量绕过。
8. 演练数据库和签名密钥备份恢复、密钥轮换和人工离线发证；签发私钥不出现在客户端和 Git 历史。
9. 同机交错比较 0.6.2 与商业版各 30 次可交互启动，目标 P95 增量不超过 100 ms；记录窗口内计时和外部计时口径，不能用一次快样本代替结果。
10. 免费版与商业版并存安装、单独升级/卸载、Windows 打开方式及便携版激活均通过；确认已有用户文件与关联不被意外更改。

## 商业假设与实施范围

默认 3 个自助名额、授权长期有效、额外换机人工核验都是可调整的产品参数。它们服务于轻量防分享目标，不能宣传成严格“三台同时在线”或“永久授权可即时收回”。

本次交付是设计与静态评审文档。价格、购买渠道、售后联系人、部署域名、实际证书和正式签名私钥尚未配置，不影响本次评审完成；真正发布前需要补齐。
